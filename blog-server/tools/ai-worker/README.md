# 服务器项目执行服务

网页代码任务只给资料所有者名单中的启用超管。输入需求后，后端持久化任务；独立 Python 服务通过回环接口和独立 WorkerKey 领取任务，再从 GitHub main 拉取完整源码，创建 `codex/ai-<任务ID>` 分支。默认通用任务不接收 `.private`；手动开启项目资料时，只附带既有知识仓储检索出的片段，不把整个私有目录挂载给执行容器。

模型使用现有 AnyRouter Responses / `gpt-6.1-sol`，只提供列文件、读源码、精确编辑和固定检查工具。宿主不向模型开放 shell、Git、数据库、合并或部署工具。检查容器没有网络，使用 UID 10001、只读源码挂载、独立复制和受限 CPU/内存，生产配置、数据库、模型密钥、GitHub 私钥均不挂载。容器内的 Go 编译缓存使用独立可写镜像层，不回写宿主或跨任务共享可写缓存。

最终差异最多20个源码/测试文件、100000字。前端执行 typecheck/test/build，后端执行串行 test/vet/build；最终检查在模型结束后重新运行。通过后网页要求显式查看差异并确认，使用差异摘要绑定发布许可；发布只推任务分支，合并与上线另行操作。每天最多2个任务，每个模型任务最多8轮，失败也计任务次数。任务租约20分钟，服务中断后到期失败，不自动重放。

服务运行目录：`/opt/yia-ai-worker`，私有设置：`/etc/yia-ai-worker`，任务源码与待审结果：`/var/lib/yia-ai-worker/jobs`。博客任务记录另存到 `ai.workspace_dir`；它与 Git 开发工作区不同，不包含执行目录配置。

WorkerKey 使用随机独立凭据，由 `YIA_AI_WORKER_KEY` 同时注入博客后端和 worker；不要复用管理员JWT或模型密钥。GitHub 部署私钥只供宿主发布分支，具有该仓库写权限；分支限制由发布器固定参数执行，不代表 GitHub 密钥自身只有分支权限。主机密钥使用经过HTTPS获取的GitHub官方公开密钥，禁止关闭SSH主机验证。

新服务器先根据 Dockerfile 构建 `yia-ai-checks:1`，准备 GitHub 凭据与环境文件，再安装 service。大型修改、依赖升级、任意脚本执行、自动合并/部署、桌面双向接续和普通附件提问不在本版能力内。检查镜像版本必须与项目依赖一致；改动依赖时由维护者重建镜像，模型不能修改锁文件或自行联网安装依赖。
